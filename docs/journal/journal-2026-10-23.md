## WebSocket, HiveMQ et tunnel Cloudflare

Le broker est consultable depuis un navigateur, en local par le port 9001 et depuis Internet par `rover.gretier.xyz` sur le port 443, chiffré en `wss`.

1. **WebSocket local.** Ajout dans `mosquitto.conf` d'un second port : `listener 9001` et `protocol websockets`, et publication du port 9001 dans `docker-compose.yml`.
2. **Test avec HiveMQ WebSocket Client** (`hivemq.com/demos/websocket-client`) : port 9001, SSL décoché. Il a fallu abonner le sujet `rover/rover-01/test` en le tapant à la main (le broker refusait la première saisie : « Invalid subscription string »).
3. **Tunnel Cloudflare `rover-vm`.** Créé dans le tableau de bord (Networking, Tunnels, Cloudflared, Docker). Le jeton est rangé dans `~/rover-stack/.env` (permissions 600), lu par le service `cloudflared` du `docker-compose.yml`. Quatre connexions enregistrées, état Healthy.
4. **Route publiée** : `rover.gretier.xyz` vers `http://mosquitto:9001` (le nom `mosquitto` est résolu dans le réseau Docker).
5. **Test final** : HiveMQ avec l'hôte `rover.gretier.xyz`, port 443, SSL coché ; les messages « bonjour » s'affichent en direct.

Le port 443 passe sur presque tous les réseaux (cégep, 4G), et la page HiveMQ, en https, n'accepte que le `wss`. L'ancien tunnel `pc-maison` (cours 4J5, `mqtt.gretier.xyz`) est éteint et n'a pas été modifié. Le broker est maintenant joignable depuis Internet : le mot de passe MQTT doit être long et unique.

## Problèmes rencontrés et correctifs

| # | Problème | Cause | Correctif |
| --- | --- | --- | --- |
| 1 | « Missing Dependencies » à l'installation de VirtualBox | Liaisons Python optionnelles | Cliquer sur Oui, aucun impact |
| 2 | Première VM inutilisable (64 Mo, disque de 2 Go, NAT) | Valeurs minimales par défaut | VM recréée : 4096 Mo, 2 processeurs, 25 Gio, accès par pont |
| 3 | La VM redémarre sur l'installateur | ISO resté dans le lecteur | Retirer l'ISO dans Configuration, Stockage |
| 4 | « Login incorrect » | Identifiant différent du nom de machine ; clavier | Utiliser l'identifiant choisi à l'installation |
| 5 | `docker run hello-world` : permission denied | Utilisateur nouvellement ajouté au groupe `docker` | Se reconnecter (ou `sudo docker`) |
| 6 | Compilation Arduino très longue | Premier build du cœur ESP32 | Patienter, les suivants sont rapides |
| 7 | MQTT : échec, code 5 | Mot de passe MQTT du `secrets.h` non remplacé | Mettre le bon mot de passe, puis téléverser |
| 8 | Pare-feu Windows : `mdns-discovery.exe` | Outil de découverte réseau d'Arduino | Annuler, inutile pour un téléversement USB |
| 9 | Commande tapée comme un chemin (`Permission denied`, `Not a directory`) | Un chemin seul est exécuté comme un programme | Utiliser `cat >>` ou `nano` pour modifier le fichier |
| 10 | HiveMQ se déconnecte à l'abonnement ; « Invalid subscription string » | Sujet saisi invalide | Retaper le sujet à la main |
| 11 | `cloudflared` : « Provided Tunnel token is not valid » | L'identifiant du tunnel avait été mis à la place du jeton | Copier la commande Docker complète, ne garder que le texte après `--token` (commence par `eyJ`) |
| 12 | `chmod600 .env` : commande introuvable | Espaces oubliés | `chmod 600 .env` |
| 13 | Dépôt du cours 4J5 : `config.h` modifié contenant de vrais identifiants | Fichier d'exemple rempli avec les vraies valeurs | Ne pas commiter ; secrets dans un fichier ignoré, exemple avec valeurs bidon |
