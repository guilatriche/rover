## Résumé de la séance

Accès à la VM à distance : un terminal SSH s'ouvre dans le navigateur à l'adresse `rover-ssh.gretier.xyz`, protégé par Cloudflare Access, grâce à une deuxième route sur le tunnel `rover-vm`. La configuration est la même que celle du cours 4J5 (applications « Browser SSH »). La commande de la LED n'est pas encore commencée.

## Ce qui a été fait

1. **Ports.** Clarification des trois portes du broker : 1883 (MQTT, réseau local), 9001 (MQTT sur WebSocket, réseau local), 443 (WebSocket chiffré chez Cloudflare, qui redirige vers le 9001 de la VM).
2. **Domaine.** `gretier.xyz` donne un nom stable et un certificat à la VM, quelle que soit sa position ou son adresse locale. Il n'expose que ce qui est publié par une route.
3. **Retour sur le cours 4J5.** Le tunnel `pc-maison` (éteint) avait deux routes : `pc.gretier.xyz` vers `ssh://localhost:22` et `mqtt.gretier.xyz` vers `http://127.0.0.1:9001`, avec deux applications Access de type Browser SSH (`pc` et `rpi-ssh`). Aucune installation n'était nécessaire sur l'ordinateur du cégep.
4. **Reproduction pour la VM.**
   - Ajout de `extra_hosts: host.docker.internal:host-gateway` au service `cloudflared` du `docker-compose.yml`.
   - Route du tunnel `rover-vm` : `rover-ssh.gretier.xyz` vers `ssh://host.docker.internal:22`.
   - Application Access `rover-ssh` : destination publique `rover-ssh.gretier.xyz`, Browser rendering SSH, règle existante réutilisée.
5. **Test** : terminal ouvert dans le navigateur, invite `rover@rover:~$`, depuis le réseau local en passant par Cloudflare.
6. **Instantané VirtualBox** pris après la mise en place.

## Problèmes rencontrés

| # | Problème | Cause | Correctif |
| --- | --- | --- | --- |
| 1 | Hypothèse fausse : SSH à distance supposait d'installer `cloudflared` sur l'ordinateur | Confusion avec la méthode SSH classique | Le rendu SSH dans le navigateur (Browser rendering) n'exige aucune installation |
| 2 | `localhost:22` ne fonctionne pas depuis le conteneur | `cloudflared` tourne dans Docker : `localhost` est le conteneur | `host.docker.internal` avec `extra_hosts` |
| 3 | Option « Browser rendering » introuvable à la création | Elle se trouve dans l'onglet Basic information | Enregistrer puis Edit, ou la chercher dans le formulaire |
